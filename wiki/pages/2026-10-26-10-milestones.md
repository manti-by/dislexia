# 10 — Milestones & build order

Part of the build plan — start at [[2026-10-26-build-plan]].

## TL;DR

Build order M0–M7 with per-milestone scope and acceptance criteria, the
dependency graph and the risk register. M0–M5 are complete; M6 (tray/lifecycle)
and M7 (packaging/QA) still carry open boxes.

---

Each milestone ends with a working `cargo run` (or bundled app) and its acceptance criteria met. Sizes: S ≤ half day, M ≈ 1 day, L ≈ 2–3 days (single developer, unfamiliar-with-GPUI baseline; GPUI familiarity roughly halves the estimates).

## M0 — Project scaffold (S)

**Scope** ([[2026-10-26-02-project-setup]]): cargo init, `Cargo.toml` deps, `main.rs` opens an 800×600 window with kit `TitleBar` and default theme; module skeleton files created empty; logging via `env_logger`; `scripts/make-icons.sh` generates `assets/` (icns + tray template PNGs) from [`media/dislexia.svg`](../../media/dislexia.svg).

**Acceptance**
- [x] `cargo run` opens the window; close quits (default behavior, fine for now)
- [x] `cargo clippy -- -D warnings` clean
- [x] API-shape notes recorded: confirmed names of `Application`, `open_window`, theme init, `component` paths for the pinned kit version
- [x] `assets/icon.icns` + `assets/tray-{16@1x,32@2x}.png` exist and are regenerated by the script

## M1 — UI skeleton, fake backend (M→L)

**Scope** ([[2026-10-26-03-ui-layout]]): sidebar + transcript + input area + send button rendered with kit components; sending appends a local echo "assistant" message (canned multi-chunk fake stream with `std::thread::sleep` on the background executor — exercises the streaming rendering path); new-chat switching between in-memory chats; markdown rendering for assistant text.

**Acceptance**
- [x] Layout matches §1 of 03 (review against the ASCII mock)
- [x] Fake stream renders incrementally with cursor, then completes
- [x] Sidebar switches chats; active highlight works
- [x] Enter/Shift+Enter behave; Send disables on empty/streaming

## M2 — Real Ollama chat (M)

**Scope** ([[2026-10-26-04-ollama-client]]): `ollama` module complete (client, types, error taxonomy) + unit tests for parsing; `Dislexia` builds requests from **hardcoded** settings struct in `main.rs`; streaming wired to `ChatStore`; Stop button + cancellation; error blocks in transcript.

**Acceptance**
- [x] Against real local Ollama: full conversation works across turns
- [x] Kill `ollama serve` → friendly error; restart → works again
- [x] Stop mid-stream keeps partial text
- [x] `tests/ollama.rs` mock-server tests pass ([[2026-10-26-09-testing]] §2)

## M3 — Settings (M)

**Scope** ([[2026-10-26-05-settings]]): settings modal UI per [[2026-10-26-03-ui-layout]] §2; JSON persistence + validation; model dropdown from `/api/tags`; connection test + status dot; client rebuild on URL change; first-run auto model select.

**Acceptance**
- [x] Fresh profile (no `settings.json`): the file is created containing the full default system prompt from `prompts/default-system-prompt.md`; **Reset to default** in the UI restores it
- [x] All settings fields round-trip through relaunch (file at the expected path)
- [x] Changing server/model takes effect on the very next send
- [x] Invalid URL/numbers show inline errors and don't corrupt the file
- [x] Settings persist through app restart

## M4 — Chat history persistence (S→M)

**Scope** ([[2026-10-26-06-chat-history]]): per-chat JSON files, load at startup, save at message granularity, sidebar groups (Today/Yesterday/Older), delete with confirm, corrupt-file tolerance.

**Acceptance**
- [x] Relaunch restores everything; unit tests for store pass
- [x] Deleting removes file + row; empty new chat never creates a file

## M5 — Theme, zcode look (S→M)

**Scope** ([[2026-10-26-07-theme]]): appearance observer + palette swap (dark/light), custom primitives (assistant bar, cursor, active-row), contrast fixes, tray template PNGs (generated from [`media/dislexia.svg`](../../media/dislexia.svg) in M0) verified and staged for M6.

**Acceptance**
- [x] Live OS appearance switch re-themes instantly
- [x] No hard-coded colors in `ui/` (`rg '#[0-9a-fA-F]{6}' src/ui` → empty)
- [x] Both palettes pass the contrast spot-checks of [[2026-10-26-07-theme]] §6

## M6 — Tray & background lifecycle (M→L; the risky one)

**Scope** ([[2026-10-26-08-tray-and-lifecycle]]): tray icon + menu + event pump + forwarding into GPUI, window show/recreate, Dock policy toggling, `cmd-w` hide, quit paths, Risk #1 investigation.

**Acceptance**
- [ ] All of [[2026-10-26-09-testing]] §3 "Tray / lifecycle" passes, incl. the 60s-alive check
- [ ] Background generation completes while windowless
- [ ] Reopen < 500ms with state intact

## M7 — Polish & packaging (M)

**Scope**: `scripts/bundle.sh`; icon polish — the [`media/dislexia.svg`](../../media/dislexia.svg) mark on a black-ink transparent canvas (updated via `scripts/make-icons.sh`, [[2026-10-26-02-project-setup]] §8); final visual pass against zcode reference; keyboard shortcuts audit; copy button; title shows model; window-min size; repo `README.md` per the content checklist in [[2026-10-26-02-project-setup]] §9; full manual QA pass ([[2026-10-26-09-testing]] §3); stretch picks if time allows (rename chats, `cmd+B` collapse, launch-at-login); window frame persistence landed with [[2026-10-26-03-ui-layout]] §6.

**Acceptance**
- [ ] Bundled `.app` passes the full manual checklist *(interactive QA — see [[2026-10-26-09-testing]] §3; the bundle builds and launches, the pointer/keyboard checklist needs a human pass)*
- [x] `README.md` complete per [[2026-10-26-02-project-setup]] §9 — pitch, quickstart, build/package, data location, credits *(screenshot pending — capture one with `cargo run` and add it to README)*
- [x] No TODOs left in code that aren't filed as stretch items

## Dependency graph

```
M0 ─┬─→ M1 ─┬─→ M2 ─→ M3 ──┐
    │       ├─→ M4          ├─→ M7
    │       └─→ M5 ─────────┤
    └─→ M6 ─────────────────┘
```

M6 only needs M0 — it can be pulled earlier if tray risk worries us; doing it **right after M2** is a reasonable de-risk move (it's the least documented integration).

## Risk register

| # | Risk | Likelihood | Mitigation |
|---|------|-----------|------------|
| 1 | GPUI quits when last window closes (breaks background mode) | Unknown | M6 first task: verify; three fallbacks listed in [[2026-10-26-08-tray-and-lifecycle]] §4 |
| 2 | tray-icon ↔ GPUI event forwarding has no stock bridge | Medium | Dedicated thread + main-thread hop; global-pointer trampoline fallback ([[2026-10-26-08-tray-and-lifecycle]] §3) |
| 3 | GPUI API drift vs. docs/examples online | High (certain) | Everything pinned through `gpui-kit` 0.8; snippets in this plan marked "verify"; M0 records confirmed shapes |
| 4 | Blocking `ureq` cancel latency on stalled server | Low impact | 30s read timeout + between-lines check ([[2026-10-26-04-ollama-client]] §6); acceptable v1 |
| 5 | Kit component gaps (e.g. numeric input UX) | Medium | All components have plain `Input` fallbacks; numbers validated in settings layer |
| 6 | Markdown renderer heavy for long chats | Low | The transcript is a plain scrolling `v_flex` (no virtualized kit list in v1); if long chats get slow, cap markdown rendering to the last N messages (M7 note) |

## Definition of Done (every milestone)

1. Acceptance boxes ticked
2. `cargo fmt --check` / `clippy -D warnings` / `cargo test` green
3. Plan docs updated where implementation diverged (plan is the contract — keep it true)
4. `cargo run` still works from a clean clone of the branch
