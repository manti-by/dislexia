# 03 — UI layout & screens

Part of the build plan — start at [[2026-10-26-build-plan]].

## TL;DR

Window anatomy — title bar, resizable sidebar, transcript, bottom-anchored
composer — plus the settings modal, the empty/error states and the key bindings
that wire it together. All stock GPUI Kit components; the only custom styling is
the palette and the 12px window controls.

---

The look is **zcode-like**: dark-first, terminal density, quiet chrome, monospace metadata, an accent-marked assistant column. Built from stock GPUI Kit components — the only custom styling is the palette ([[2026-10-26-07-theme]]) and a handful of layout wrappers.

> Component names below reference the GPUI Kit component library (`gpui_kit::component`). Confirm exact names/props against [gpui-kit docs](https://gpui-kit.com) at implementation time; the mapping is deliberately conservative.

### Regions

| Region | Implementation | Notes |
|---|---|---|
| Title bar | kit `TitleBar` | Shows a 12px app name + active model; right side: settings icon button, new-chat icon button. The native AppKit traffic lights are hidden and replaced by custom 12px controls (`src/ui/title_bar.rs`). |
| Sidebar (resizable, default 150px, 150–420px) | `h_resizable` split + a scrolling `v_flex` list | "New chat" button at top; grouped chat list (Today / Yesterday / Previous 7 days / Older — see [[2026-10-26-06-chat-history]] §4); hover a row for its delete action. Settings lives in the title bar, not here. Drag the divider to resize; the sidebar keeps its width when the window resizes. Collapsible via `Cmd+B` (stretch, not built). |
| Transcript | scrolling `v_flex` (no virtualization yet) | Full-width column with a 16px inset; text wraps to the pane width. Auto-scroll to bottom while streaming unless the user scrolled up. |
| Message row | custom light wrapper (see §2) | No chat bubbles on the assistant side — flat blocks, zcode-style. |
| Input area | kit `TextArea` (auto-grow 4–12 rows) inside a floating rounded box at the window bottom; the Send/Stop button is overlaid inside the box's bottom-right corner (zcode-like; changed from the original border-top bar in M7 polish) | `Enter` sends; `Shift+Enter` newline. While streaming the button becomes **Stop** (destructive variant). Disabled (dimmed) while streaming. |

### Message row anatomy

```
user:      <surface panel bg, rounded 6, max-width 520, own column>
assistant: left 2px accent-colored bar + markdown body (kit `TextView`),
           dim monospace meta line above (model · elapsed seconds), streaming cursor "▌"
error:     assistant-style block with error-colored bar + error text + "Retry" text button
```

Streaming cursor: append `▌` while `status == Streaming`; swap to nothing on completion. Show elapsed time from first chunk to done-chunk (stats arrive in the final chunk — [[2026-10-26-04-ollama-client]] §5).

## 2. Settings screen

Kit `Dialog` centered over a scrim, 560px wide, sections separated by hairlines. Changes are **saved on every field change** (debounced 300ms) — there is no OK/Cancel in v1.

**Connection**
- Server URL — `Input` (mono font), validated on blur; invalid URL → inline error hint
- Status line + **Test** button → calls `/api/tags`: `● Connected — 5 models` / `● Cannot reach server` (with the Ollama error text)

**Model**
- Model — `Select` populated from `/api/tags` (fetched when the dialog opens and via refresh icon)
- `Pull model…` link → opens `http://127.0.0.1:11434` in browser? No — v1 shows a hint row instead ("Run `ollama pull <name>` to add models") to avoid managing pulls.

**Parameters**
- System prompt — `Textarea`, 6 rows, placeholder "No system prompt", **prefilled with the default text-fixer prompt** ([[2026-10-26-05-settings]] §1.1); a **Reset to default** button restores the embedded prompt
- Temperature — numeric `Input` (0.0–2.0, step 0.1) with slider? v1: numeric input only
- Top P, Top K, Num predict, Num ctx, Repeat penalty — numeric `Input`s, empty = "not sent" (Option)
- Seed — numeric input, empty = random

There is no **General** section yet: `launch_at_login` exists in the schema but its switch stays disabled until the `SMAppService` work in [[2026-10-26-08-tray-and-lifecycle]] §8.

All fields map 1:1 to the Settings schema in [[2026-10-26-05-settings]].

## 3. Empty & edge states

| State | Presentation |
|---|---|
| No chats yet | The store always starts with one untitled chat, so the sidebar shows only "New chat"; an empty transcript shows the centred hint "Start a conversation with a local model ↓" |
| No model selected | Sending still appends the user message, then an assistant-style error block: "No model selected. Open Settings → Model." On first successful connect the first model from `/api/tags` is auto-selected (silently, logged at info) |
| Server unreachable on send | Assistant-style error block: "Can't reach Ollama at `<url>` — is `ollama serve` running?" |
| Model not found (404 from Ollama) | Error block with the mapped wording: `Model "<name>" not found. Open Settings → Model.` |
| Empty input | Send disabled |
| Streaming in progress, user opens another chat | Allowed; generation continues writing to its own chat (single in-flight generation still enforced per app, not per view) |

## 4. Interaction details

- Clicking a chat in the sidebar: switches `active_chat_id`, transcript scrolls to bottom, input focused.
- `New chat` clears to a fresh untitled chat (created lazily on first send — see [[2026-10-26-06-chat-history]] §3).
- Hover a sidebar chat → delete action, confirmed via an alert dialog. Rename is a stretch item (the title field is just a string).
- Hover a message row → small copy icon (copies raw text to clipboard via GPUI clipboard API).

## 5. Theming hookup

All colors come from the kit theme (`ActiveTheme`) — screens must contain **no hard-coded colors**; the only hex values live in [[2026-10-26-07-theme]]. Typography: UI font default, message body 13px, meta lines `.font_family("mono")` 11px + dim.

## 6. Sizing & window

- Default window: 800×600, min 480×360.
- The last frame is persisted (`settings.json` → `window_frame`, [[2026-10-26-05-settings]] §1) and restored on next launch, including reopening on the display it was saved on (`DisplayId` resolved from the persisted display UUID). A frame that no longer fits its display — monitor unplugged, resolution changed — is clamped: never below the 480×360 minimum, never larger than the screen, and at least 80 points of the window stay inside the display on both axes so the title bar is always grabbable. A missing frame (first run) centres 800×600 on the primary display.
- Saving uses the existing debounced settings write ([[2026-10-26-05-settings]] §4): `cx.observe_window_bounds` fires on both move and resize, so a drag writes once, 300ms after it settles. Native fullscreen reports the screen rather than the frame the user picked, so it does not overwrite the last windowed frame.
- Window title shows active model; set via window titlebar API or TitleBar label.
- Window controls: three 12px circles (close/minimize/zoom) at the leading edge, 8px apart. macOS 27 draws its native traffic lights at 14px and AppKit does not scale them, so `platform::macos::hide_window_buttons` hides the native ones and the kit `TitleBar` hosts the custom controls (`src/ui/title_bar.rs`). Hovering the cluster reveals the glyphs; clicks map to `remove_window` / `minimize_window` / `zoom_window`.

## 7. Actions & keyboard shortcuts

```rust
actions!(dislexia, [NewChat, Send, StopGeneration, OpenSettings,
                    FocusInput, HideWindow, QuitApp, EscapePressed]);
```

| Shortcut | Action |
|---|---|
| `Enter` (input focused) | Send |
| `Shift+Enter` | Newline |
| `cmd-n` | New chat |
| `cmd-,` | Open settings |
| `esc` | Stop generation (when the composer is empty); otherwise closes the settings dialog |
| `cmd-w` | Hide window (to tray — not quit; see 08) |
| `cmd-q` | Quit (only path besides tray menu) |

Bind via `cx.bind_keys([KeyBinding::new("cmd-n", NewChat, None), ...])` in `main.rs`; the bindings and their `actions!` names are the verified list. Actions dispatch from `Dislexia::on_action` handlers on the root element. Menu-bar equivalent menus are out of scope for v1 (tray menu covers it).
